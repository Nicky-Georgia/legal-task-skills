# Redline assignments and reference work product

## Assignment and matter files

Name the exact editable source DOCX by filename and version. State the represented
party, recipient, negotiation stage, objective, and practical constraint. Specify
the redline filename and any required native Word comments, clean companion, or
separate internal communication. Give related documents distinct roles. For
example, a counterparty draft supplies the text to revise, instructions and
negotiation history supply authority and context, and a published or signed
final may illustrate that a matter later concluded. Put the actual draft, any
controlling approvals or playbook, and any needed incorporated documents within
the solver's materials. Keep the reference answer and any answer-revealing later
versions outside those materials unless the assignment specifically uses them.

A useful naming pattern from a supplied formatting sample is an editable version
with a stable document identifier, successive revisions with the same identifier
and distinct version numbers, and a separately labeled final. That sequence is
an illustration. Follow the actual task's file conventions and deliverables.
Do not import the sample's matter facts, instructions, or files, assume a clean
companion is always required, or infer the comparison base from a filename.

If the baseline or controlling materials are missing, stop work that depends on
them and identify the exact missing inputs. Continue supported independent
repairs. Rejecting a reference redline can yield a comparison candidate, but it
cannot establish the authentic baseline, reproduce separate approvals, or prove
that all original terms were tracked. Do not promote such a candidate to the
solver's source draft or treat the reference as evidence of authority.

## Revision and verification

Identify each file's relationship to the named baseline. Preserve signed source
evidence and existing source markup when it matters. Work on a copy. Use native
Word changes and native comments when requested, preserving sections, numbering,
defined terms, cross-references, tables and fields. Track the smallest coherent
unit of change. Keep comments short, anchored to the operative text, and suited
to the intended reader. Keep internal approval advice in the assigned internal
channel if the redline is intended for the counterparty. Do not mark editorial
changes to the exercise itself as if they were the represented party's positions.

Render and inspect the marked document and its accepted projection. On a scratch
copy, reject the redline and compare the resulting operative text and structure
against the exact named baseline. If the baseline itself contains markup, first
establish which projection and annotations form the agreed starting point and
reject only the new layer. Verify that accepting the intended changes yields the
proposed revised instrument, including tracked numbering, moves, formatting and
table changes where relevant. Compare any required clean companion with that
accepted state. Check native revision and comment anchors structurally as well
as in the render and review all substantive edits against the governing record.
Keep the accepted and rejected QA copies in scratch unless expressly deliverable.

Score observable drafting effects and instructions the solver can apply with the
supplied record. Align comment and internal approval criteria with the actual
audiences. A usable alternative can earn credit when it meets the approved position
and protects the same legal or commercial interest.

Finalize a verified native redline using the work-product mode in
[Word finalization](word-finalization.md). Use the default finalization mode for
ordinary clean Word deliverables. Never accept the assigned edits merely to pass
metadata checks.
