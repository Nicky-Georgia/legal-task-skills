# Rubric repairs and delivery contract

## Repair criteria against the revised task

Read the full rubric, including supporting details, scores/weights, penalties,
dependencies, and any grading instructions. Anchor a correction to the criterion
ID or exact existing title. Fix demonstrable errors and affected dependencies;
leave sound criteria alone.

Check that each criterion asks for observable work the assignment actually
requires and that the supplied record permits. Reward legally defensible
alternatives, conditional advice when facts warrant it, and material reasoning,
not exact reference phrasing or an unsupported preferred outcome. Do not reward
a legal assertion merely because it appears in the reference.

Remove double counting and contradictory requirements. Separate independently
scorable elements when an all-or-nothing bundle creates a material distortion;
retain integrated criteria where the conditions belong to one coherent task.
Cover missing essentials such as usable relief or operative drafting when the
assignment requires them. Do not invent numerical limits on criterion counts.

Keep IDs and scores unless the correction requires changing them. A split or
merge must specify which old entries are removed, where replacements go, and
how weights transfer. Check that the maximum score and penalties remain
coherent; explain an intentional total-score change. Do not invent weights
when the original schema has none. Preserve the platform's actual field names.

## Plain-text correction format

Use separate blocks of ordinary chat text, not a table, DOCX, JSON file, or code
fence. Clearly separate the locator/action from text intended for the form.
Return the complete new value of each changed field, not an ambiguous fragment
requiring the user to reconstruct it. Only include fields that need editing.

Example layout (illustrative field names only):

Rubric corrections

Criterion NOTICE-02 — replace Criterion

[Complete replacement value for the Criterion field.]

Criterion NOTICE-02 — replace Supporting details

[Complete replacement value for the Supporting details field.]

Criterion DUP-04 — delete this criterion.

New criterion after NOTICE-02

Title: [New title]
Criterion: [Complete value]
Supporting details: [Complete value, if the form uses it]
Weight: [Only if the original schema uses a weight]

Put reasons in the separate overview, not inside the paste-ready criterion.
If no rubric change is justified, say “No rubric corrections needed.”

## Prompt corrections

When the prompt is a form field, provide the complete replacement field text
under “Prompt correction,” separate from rubric edits. Preserve its scope,
audience, constraints, dates, and deliverables except for supported corrections.
Do not add requirements merely to excuse omissions in the reference. If the
prompt is missing, say what cannot be checked and do not reconstruct it from
the rubric as though it were supplied.

## Final response

Deliver in this order, using short labels only where helpful:

1. Changed work product in the assigned format, linked by original role and
   recognizable filename.
2. Exact rubric corrections in plain chat text.
3. Exact prompt field correction, only when needed.
4. Separate overview: file/passage or criterion, what changed, and why, including
   meaningful improvements from independent analysis; material review points
   rejected or adjusted and their evidence-based reason; unchanged files or
   groups; actual inspection coverage and any unresolved issue or
   verification/conversion limitation. Distinguish files found sound from files
   not examined in depth; do not imply an exhaustive audit of a sampled pack.

Do not return a rewritten rubric document unless separately requested. Do not
deliver internal ledgers, clocks, source caches, render images, or comparison
files. A ZIP of only the final Word files is optional for convenient download;
do not imply an unchanged file was revised. Retain recognizable basenames in
role folders, avoiding process labels such as “AI cleaned” or “agent edited.”

The overview must not claim all recommendations were incorporated when some
were rejected, all sources were verified when some were unavailable, or all
files changed when some were deliberately left intact. Briefly identify the
measured active session time if useful; the repeated Word time value is not a
per-file billable-time allocation and must not be summed across files.
